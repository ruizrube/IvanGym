# AGENTS.md

## Project overview
IvanGym is a mobile-first, offline-capable web app (PWA) for Iván's gym routine: flexible, editable routines, per-set weight logging, extra activities (cardio, walking…), history calendar, progress charts and an evidence-based coach that analyses the history and proposes routine changes. UI language is Spanish. See `docs/PLAN.md` for the full spec.

It is plain HTML, CSS and JavaScript (ES modules) with **no build step**, deployed to GitHub Pages ("Deploy from branch", `master`, root). Data lives in `localStorage` (`ivangym:v1`) with JSON export/import.

## Structure
- `index.html` – shell (top bar, `<main id="view">`, bottom tab bar, dialog, toast).
- `js/app.js` – hash router (`#/hoy`, `#/dia/YYYY-MM-DD`, `#/historial[/YYYY-MM]`, `#/progreso[/exId]`, `#/musculos`, `#/rutinas[/id|nueva]`, `#/ajustes`) and views.
- `js/data.js` – movement patterns (`PATTERNS`), exercise catalog (muscles, pattern, tips, YouTube URLs), seed routines, activity types, tips, motivational quotes.
- `js/muscles.js` – muscle groups (`MUSCLES`: Spanish name, aliases used in `EXERCISES.primary/secondary`, where/use) and the SVG body map (front/back polygons adapted from react-body-highlighter, MIT). New muscle names in `data.js` must be added as aliases here.
- `js/storage.js` – localStorage model (sessions, routines, videos, notes), history queries, export/import.
- `js/coach.js` – evidence-based analysis of the history (weekly volume and frequency per muscle, push/pull and lower/upper balance, stagnation, detraining, fatigue, cardio vs. WHO targets) and routine-change proposals. Rules and sources: `docs/INVESTIGACION-ENTRENAMIENTO.md` §3; each alert carries its evidence level (`EVIDENCE`) and source.
- `js/dates.js` – `YYYY-MM-DD` date helpers shared by the other modules.
- `sw.js` – service worker (precaches app shell and GIFs). **Bump `VERSION` and update `SHELL`** when adding/renaming static files.
- `img/exercises/*.gif` – seed exercises: generated by `tools/crop_gifs.py` from the collages in `docs/`; catalog alternatives (with `src`): generated by `tools/fetch_gifs.py` from free-exercise-db (public domain, Unlicense).

## Routines and exercises
The exercise catalog lives only in code (`js/data.js`, see the comments above `EXERCISES`); every exercise needs a `pattern` (key of `PATTERNS`) so the coach can propose same-pattern swaps. `ROUTINES` in `data.js` are only the seed: on first load they are copied to storage, and from then on routines are edited in the app (`#/rutinas`) and saved/exported with the user's data. A routine's `since` is the start date of its current version (reset when its exercise set changes); `snoozeUntil` postpones proposals. Routine and exercise ids are persisted in users' data: never change or reuse them (`nextRoutineId()` never reuses ids found in history); retire routines with `active: false`. Each routine has its own `color` (applied via the `--rc` CSS variable). GIFs live in `img/exercises/<id>.gif` and are precached at runtime for active routines (`precacheGifs`), not listed in `sw.js`. `checkData()` logs `[IvanGym]` console errors for invalid data.

## Working rules for agents
- Keep changes small and focused on the task.
- Do not introduce frameworks, bundlers or npm dependencies.
- Use relative paths only (the site is served under `/<repo>/` on github.io).

## Local development
- Serve the folder: `python3 -m http.server 8000` and open http://localhost:8000
- Regenerate GIFs (needs Pillow): `python3 tools/crop_gifs.py` (seed collages) and `python3 tools/fetch_gifs.py` (catalog exercises with `src`; downloads from GitHub)

## Coding conventions
- Use 2-space indentation, LF line endings, no trailing whitespace, final newline.

## Validation
- Check the affected screen in a mobile viewport in the browser (DevTools device mode).
- Check the browser console for errors; test offline mode after changing `sw.js`.
